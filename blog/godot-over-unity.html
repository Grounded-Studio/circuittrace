Why we chose Godot over Unity.

📅 18 October 2026 · ⏱ 6 min read · ✍️ Grounded Studio

Every time I tell another dev that Circuit Trace is built in Godot, they ask the same question. "But why?" As if the answer must be a horror story about Unity. It isn't. The honest answer is more boring, and I think more useful.

The 2023 licensing shock mattered less than you think

The obvious place to start — the Unity Runtime Fee drama in late 2023 — is actually the least interesting part of the decision. Yes, it rattled every indie I know. Yes, Unity walked a lot of it back. But by then enough of us had already looked at the exit door and found something worth walking through.

What the drama really did was give me permission to evaluate alternatives seriously. Before 2023 I would have assumed "serious mobile game = Unity" without checking. After 2023 I spent two weeks building the same prototype in both engines and let the result decide.

Prototype #1: a flow puzzle in Unity

Three days to install, open a project, and get a tap-to-drag grid working. Perfectly fine. The input system is powerful. The tooling is deep. There are 90 tutorials for everything, so you're never truly stuck.

What bothered me, in order of annoyance:

  • Editor install was 7 GB. After Android build tools, another 4 GB. Then the Hub itself. My laptop fan heard every save.
  • The scene file is binary. You can't diff a scene change in git. For a solo dev that's inconvenient. For a team it's a tax.
  • C# is lovely but needs a lot around it. Visual Studio, package manager, serialisation attributes, scriptable objects, assembly definitions. For a puzzle game this is a lot of wiring.
  • The empty project built to 32 MB. For a game where the entire gameplay logic eventually weighed less than 2 MB of GDScript, that felt wrong.

Prototype #2: the same thing in Godot

Downloaded the editor. 95 MB. Single executable. Opened it. Made the same tap-to-drag grid in a long afternoon.

Three things clicked:

  • Everything is a scene. A grid is a scene. A button is a scene. The whole main menu is a scene that references other scenes. The mental model of "nested scenes composing a game" matched how I actually think about UI, which I spent most of my time on.
  • GDScript is Python-ish. Not better than C#, just lighter. No build step. Edit, hit F5, see the change. For iteration on tiny puzzle mechanics this is faster than it has any right to be.
  • The scene files are text. `.tscn` files are plain text, diffable, mergeable. I can see in a PR exactly what someone changed about a scene. For future-me reviewing past-me's work, this matters more than I expected.

The things Unity still does better

I don't want to be the person pretending Godot is already Unity. It isn't, and these gaps are real:

  • 3D tooling. If I was building a racing game or a shooter, I'd probably still pick Unity. Godot's 3D is improving fast but the ecosystem for 3D assets, pipelines, and third-party plugins is nowhere near.
  • Documentation depth. Unity's docs cover edge cases I never knew existed. Godot's docs are good; Unity's are great.
  • Hiring. If I ever grow Grounded Studio past "me," there are 10 Unity devs for every Godot dev on the market. For a solo project this is zero issue; for a team of five it's a real one.
  • Big-brand asset store. Need a quick dialogue system or a shader bundle? Unity Asset Store has 50 options. Godot's AssetLib is smaller and curation is uneven.

What tipped it for Circuit Trace specifically

Three things made Godot the obvious pick for this project:

1. The game is UI-heavy. Circuit Trace is a touchscreen puzzle with menus, cards, badges, a theme system, a puzzle editor. 2D grids and vector art. Godot's control-node UI system clicks for this. Unity's uGUI is powerful but feels like fighting a 3D engine to render a flat screen.

2. I needed APK size to stay small. Players on budget Android phones in cheaper markets won't download a 60 MB puzzle game. Our released AAB sits around 62 MB with 5 modes, 500+ hand-crafted puzzles, and all the UI assets. The equivalent Unity build would almost certainly be bigger before optimisation, and the optimisation itself eats a weekend.

3. The licensing is just MIT. No install fee, no runtime fee, no "we might change this later" asterisk. I don't have to keep an eye on Godot's business model because it doesn't have one that touches me. For a solo dev shipping a €0 game with optional €3.99 Remove Ads, that peace of mind compounds every month.

Should you use Godot?

Honest answer: probably test both for a weekend on your actual project idea. The right engine depends on what you're building, not what the internet shouts about.

  • Building a 2D puzzle, platformer, roguelike, or UI-heavy mobile game? Try Godot first. It fits.
  • Building a 3D shooter, driving sim, or anything with heavy asset pipelines? Start with Unity (or Unreal). Godot can do it, but you'll be fighting rougher edges.
  • Hiring devs for a studio? Pick the engine your region hires for. In most of Europe that's still Unity.
  • Scared of Unity's business model long-term? Godot is MIT. That's not a feature, it's an absence of a worry.

Three years in

Circuit Trace is my first shipped Godot game. The next three Grounded Studio projects are also Godot. Not out of ideology — I like Unity fine — just because for the kinds of games I want to make, as a solo dev who ships things that need to be small, fast, and quiet, Godot keeps winning.

If you're on the fence, download the 95 MB editor and prototype your actual idea for a weekend. The engine will tell you.

Circuit Trace is built in Godot 4.7 and lives at circuittrace.app. The engine itself is at godotengine.org.
